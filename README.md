# File Masking Tool

Windows 11 / Windows PowerShell 5.1 で、設定した項目だけをローカルでマスキングするツールです。固定長テキスト、CSV、Excel `.xls` / `.xlsx` を処理します。Pythonや外部サービスは使用しません。

別PCで作業を引き継ぐ場合は、[HANDOFF.md](./HANDOFF.md)を参照してください。

## 重要な安全上の注意

- 入力ファイルは変更せず、別の出力先に処理結果を作ります。入力と出力を同じパスにする設定は拒否されます。
- レイアウトに指定したフィールドだけを変換します。未指定のバイト、列、セル（FILLERを含む）は元のままです。未指定箇所に個人情報がないことを、ツールは判定しません。
- 変換表にない値、範囲の不整合、変換後の幅超過などは処理失敗になります。未変換の値を成功出力に通しません。
- レポートに元値・変換後の値・セル値は記録しません。ログやレポートが値を含まないことは、出力ファイル全体の匿名性を保証するものではありません。
- 本番データと変換表は管理下の端末で扱い、組織の持ち出し・生成AI利用ルールに従ってください。出力全体を確認してから利用してください。

## 動作環境と実行

- Windows 11、Windows PowerShell 5.1
- 固定長／CSVの高速処理コアは、初回実行時に.NET FrameworkのC#コンパイラーを使ってメモリ内でビルドします。別途の実行ファイルやPythonは不要です。
- C#コンパイルが利用できない／失敗する場合、通常実行は処理開始前に失敗（終了コード`2`）します。遅い処理へ黙って切り替えることはありません。`-Help`と`-ValidateOnly`はコンパイル不要です。
- Excel `.xls` / `.xlsx` の処理には、登録済みのOffice Excel COM（Office 2024等）が必要です。
- 出力先ディレクトリは事前に作成してください。

設定例を実データの場所とレイアウトに合わせて編集し、最初に検証します。

```powershell
.\MaskingTool.ps1 -Config .\config.example.json -ValidateOnly
```

検証後に実行します。

```powershell
.\MaskingTool.ps1 -Config .\config.example.json
```

ヘルプ:

```powershell
.\MaskingTool.ps1 -Help
```

`-ValidateOnly` は設定構造、ファイルパス、形式ごとのレイアウト制約などを検査し、出力を作りません。変換表の実データや各レコードの変換可否は、実行時に検査されます。

## 設定ファイル

[config.example.json](./config.example.json) は合成パスを使った例です。`Mappings` に変換表、`Jobs` にファイルごとの処理を記述します。変換表は「変換前値<TAB>変換後値」の2列です。文字コードとキーの前後空白ルールを明示してください。

`Mode` はファイルごとに選びます。

- `Sample`: `SampleCount` と32-bit整数の`Seed`を指定します。同じ入力・設定・シードでは同じ行／レコードが選ばれます。出力は入力順です。
- `All`: 全レコードを処理します。`SampleCount` と`Seed`は不要です。

### 固定長テキスト

バイト位置は1始まりです。未指定範囲は元のバイトを保ちます。

- no-newline fixed-widthの3000-byte recordsは`RecordWidthBytes: 3000`、`RecordTerminator: "None"`とします。ファイルサイズがレコード幅の整数倍でなければ失敗します。
- 固定長テキストとCSVの文字コードはcp932（設定値`"932"`）に限定します。UTF-8、UTF-16等は設定検証時に拒否します。変換表の文字コードは別に指定できます。
- 150-byte recordsの例は`RecordWidthBytes: 150`と`RecordTerminator: "CRLF"`です。レコード本体は150バイトで、CRLFは別扱いです。`LF`も指定できます。
- 物理的に分割された同一項目は`Segments`に論理順で範囲を記述します。セグメントを連結して一度だけ変換し、元の各範囲に戻します。例では3桁と7桁の組合員番号を変換します。
- `PadSpace`は`Half`または`Full`を指定します。変換後の値がフィールド幅に収まらない場合、切り捨てずに失敗します。

### CSV

`ContainerMode: "Records"`はCSVの論理レコードを扱います。区切り文字、引用符、引用符内の改行、`""`エスケープを解析します。シリアライズ時も元フィールドのquote state（引用符付き／なし）を維持します。変換後の値により引用符が必要になるのに、元フィールドが引用符なしの場合は、引用符状態を変えずに表現できないため失敗します。

`ContainerMode: "FixedWidthNullPadded"`は、固定バイト幅のCSVレコードと末尾NUL埋めを扱います。`RecordWidthBytes`、`NullPadByte: 0`、レコード終端を明示してください。末尾の連続したNULだけをパディングとして取り除いて解析し、出力を同じバイト幅に再パディングします。途中のNULや幅超過は失敗です。NULパディングと通常文字内のゼロバイトを区別できないため、固定幅NULモードはUTF-16／UTF-32では利用できません。

### Excel

Excel COMで入力ブックの複製を処理し、入力と同じ拡張子で出力します。`Layout.Sheets`で全シートを列挙し、各シートを`Data`または`NonPersonal`として指定してください。`NonPersonal`には、個人情報を含まないことを確認した上で`NonPersonalConfirmed: true`が必要です。サンプル時は各データシートの見出しとサンプル行を保持します。数式は計算後の値に置き換えられます。

コメント、ハイパーリンク、文書プロパティなどのauxiliary contentは初版で完全削除しません。検出された場合はレポートに警告します。警告がないことも、ブックに個人情報がない証明にはなりません。`.xls` / `.xlsx`双方のExcel COM統合テストは、Excelがインストールされた環境で確認してください。

## 実行結果と終了コード

実行レポートはJSON形式で標準出力に表示されます。ジョブ状態、読み書き件数、経過時間、値を含まないエラー、警告が含まれます。

- `0`: すべてのジョブが成功
- `1`: 1件以上のジョブが失敗（ほかのジョブは続行）
- `2`: 設定、実行時コンパイル、変換表の事前読み込み、または実行モジュール読込の失敗

失敗したジョブの未完成一時出力は削除されます。成功した出力だけを完成ファイルとして公開します。

## 合成データの性能計測

固定長とCSVを各300,000レコードの合成データで測定します。C#コアの初回コンパイル、合成データ生成、変換表読込、固定長処理、CSV処理を別々に表示します。Excelは小規模な合成ブックを別に計測し、COMが利用できない場合はBLOCKEDと表示します。計測中に本番ファイルを読み込まず、生成する値も表示しません。

```powershell
.\tests\Measure-Performance.ps1
```

確認用に件数を小さくする場合は、たとえば`-RecordCount 10000`を指定できます。既定値は300,000件です。

この計測は環境比較用であり、処理時間のSLAを保証しません。

## 開発者向けテスト

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\tests\Run-Tests.ps1
```

Excel COM統合テストは、Office Excel COMが登録されていない環境では明示的にBLOCKEDになります。BLOCKEDはテスト成功として数えません。
