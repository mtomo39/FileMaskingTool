# 本番ファイルのマスキングツール設計

**Status:** ユーザー確認待ち  
**Date:** 2026-10-04

## 1. 目的

Windows 11上で、本番データを管理下から持ち出さずにファイル単位でマスキングし、生成AIに入力形式を説明するためのサンプル、または開発用のマスキング済みファイルを作成する。

対象のファイル形式は、固定長テキスト（改行なし／改行あり）、CSV、Excel 97-2003 `.xls`、Excel Open XML `.xlsx`。1万〜30万件程度のファイルと、最大約30万件の既存変換表を扱う。Pythonや追加の製品依存は導入せず、PowerShellとWindows上の.NET機能を使う。Excelファイルの加工にはインストール済みのOffice 2024を使用する。

## 2. 前提と成功条件

- 元ファイルは変更しない。出力先を別途指定し、処理中の個人情報ファイルを不要に複製しない。
- ファイルごとに「指定件数の再現可能なランダムサンプル」または「全件」を設定できる。
- レイアウトに明記した個人情報項目のみ、対応する変換表を使って変換する。
- 未指定箇所はFILLERとして保持する。FILLERや未指定セルを安全と自動判断しない。
- 変換表にない値、レイアウト不整合、変換後の幅超過等で未加工値が出力に残る場合は、そのファイルの処理を失敗させる。
- 元データ、変換前後の値、セル値はログに出さない。
- 出力は形式ごとの完全性検証を通過してから完成ファイルとして確定する。
- 固定長処理の性能目標は初版では固定しない。代表サイズの合成データで計測する。

## 3. 実行方式

PowerShellスクリプトとJSON設定ファイルを提供する。JSONには処理対象ファイル、出力先、ファイル形式、文字コード、サンプル／全件モード、レイアウト、変換表、フィールドごとの変換ルールを記述する。

スクリプトは設定を読み、全ジョブの静的な妥当性検査を行う。その後、変換表をメモリ上の検索表にロードし、ファイルを形式別に処理する。ファイルごとに一時出力へ書き、処理・検証が成功した場合のみ完成出力として確定する。元ファイルと出力ファイルが同じパスになる設定は拒否する。

## 4. 変換表とフィールド変換

### 4.1 変換表

既存のタブ区切りテキストを利用する。各レコードは変換前値と変換後値の2フィールドとし、変換表ごとの文字コードを設定できる。読み込み時に検索キーをハッシュテーブルへ格納し、30万件規模でも各フィールドの照合が線形検索にならないようにする。

- 同一変換前キーが複数回現れ、変換後値が一致しない場合は設定エラーとする。
- 変換前値の正規化はフィールドルールに従う。
- 変換後値を既定の値で黙って上書きしたり、見つからないキーを元の値のまま通したりしない。

### 4.2 固定長のフィールド

レイアウトは1始まりの`startByte`と`byteLength`で指定する。内部処理では0始まりへ変換する。レコード幅、文字コード、レコード終端（なし、LF、CRLF）はファイルごとに明示する。

各変換項目には、少なくとも次を指定する。

- 変換表の名前
- 前後空白の除去ルール（半角スペース、全角スペース、または除去しない）
- パディング文字（半角スペースまたは全角スペース）
- 対象の物理バイト範囲

氏名など可変長の値は、入力値と変換表の変換前キーに同じ前後空白正規化を適用して照合する。変換後値は指定文字コードでバイト列へ変換し、フィールド幅まで指定のスペースを末尾に追加する。変換後値が幅を超える場合、または残りバイト数を選択したスペースのバイト数で正確に埋められない場合、切り捨てずに失敗させる。

記載のないバイト範囲はそのまま保持する。レイアウト検査では、対象範囲の重複、レコード外へのはみ出し、レコード幅との不整合を拒否する。

### 4.3 分割された固定長フィールド

複数の物理範囲を一つの論理値として変換するルールを固定長に限って提供する。各範囲は論理値内の順序で設定する。

例として、組合員番号の先頭3桁が1つの場所、4〜10桁目の7桁が別の場所にある場合：

1. 先頭3桁と後ろ7桁を指定順に連結し、10桁の論理値を作る。
2. 組合員番号の変換表を一度照合する。
3. 変換後の10桁を先頭3桁と後ろ7桁に分け、元の各範囲へ書き戻す。

論理値の長さが10桁でない、どちらかの範囲が欠落している、または範囲が他フィールドと重なる場合は失敗させる。桁の先頭ゼロは文字列として保持する。

### 4.4 CSV・Excelのフィールド

CSVの対象項目は列名または列番号で指定する。列区切り、引用符、ヘッダー有無、文字コードを設定し、引用符で囲まれた区切り文字や改行、`""`エスケープを単純分割で誤解析しない。BOMがある場合は設定した文字コードとの一致を検証し、出力でもBOMの有無を保つ。解析時に各フィールドの引用符状態（引用符付き／なし）を保持する。出力でも元が引用符付きのフィールドは引用符付き、元が引用符なしのフィールドは引用符なしを維持する。変換後に区切り文字、引用符、改行等を含み引用符が必要となる元引用符なしフィールドがあれば、自動で引用符を追加せず、そのファイルをエラーにする。出力では値、引用符状態、列順を保つ。

CSVの格納方式として、通常のCSV論理レコードに加え、レコード単位の固定バイト幅と末尾NUL埋めを設定できる。固定幅モードでは`recordWidthBytes`（レコード終端を除いたデータ幅）とレコード終端（なし、LF、CRLF）を指定する。レコードをバイト幅単位で切り出し、末尾の連続した`0x00`だけをパディングとして除去してからCSVとして解析する。`0x00`はパディング専用とし、CSVフィールド値には使用しない。変換後はCSVを再構成し、同じレコード幅になるまで末尾に`0x00`を付け直す。カンマのバイト位置は変換値のバイト長に応じて変わり得るが、CSV上の列順・列数と固定レコード幅は保つ。CSV本体が幅を超える場合、NULがパディング以外の位置に現れる場合、または終端・幅が不正な場合はエラーにする。

固定幅NUL埋めモードはUTF-16／UTF-32では使用しない。これらの符号化では通常の文字列にも`0x00`バイトが含まれ、NULパディングとの判別ができないためである。`nullPadByte`は設定で明示的に`0`を指定する。

Excelはブックごとに対象シート、見出し行、データ範囲、対象列、変換ルールを指定する。列の見出しまたは番号を利用する。固定長での分割フィールド変換は初版の対象外。

## 5. ファイル形式別処理

### 5.1 固定長テキスト

- 改行なしファイルは行関数で読み込まず、レコード幅単位のバイトストリームとして処理する。サイズがレコード幅の倍数であることを事前確認する。
- 改行ありファイルは設定された終端バイトを認識し、終端以外の各レコードが設定幅と一致することを確認する。
- 全件モードは順次処理する。
- サンプルモードは固定シードの再現可能な抽出を行い、抽出後の出力は入力順に保つ。
- 改行なしファイルを未加工の改行付き中間ファイルへ変換しない。出力の改行有無は元ファイルと同じにする。必要な場合に限り、マスキング済み出力へレコード終端を追加する設定を認める。

### 5.2 CSV

CSVをストリーム処理し、全件または指定件数の再現可能なランダムサンプルを出力する。通常モードはCSV構文で論理レコードを識別し、引用符で囲まれた改行も処理する。固定幅モードは設定幅でレコードを切り出し、各レコードの末尾NULパディングを除いてから解析し、再構成後に同じ幅まで再パディングする。ヘッダーがある場合、サンプル出力にも保持する。引用符状態を含めて再構成し、変換後の値が元の引用符状態のまま有効に表現できない場合は、そのファイルをエラーにする。

### 5.3 Excel `.xls`／`.xlsx`

PowerShellからOffice 2024のExcel COMオートメーションを利用する。入力の複製を加工し、出力は入力と同じ形式で保存する。Excelはマクロを実行しない設定で起動する。

- 対象ブックの全シートについて、対象データ範囲と個人情報を含まない範囲を設定で明示する。
- サンプルモードでは、各対象データシートの見出し行と指定件数の再現可能なランダム行を残す。シート名と基本的なセル書式を保つ。
- 数式は計算後の値に置き換える。対象セルは値に対してマスキングを適用する。
- 保存時の形式変換や互換性警告を黙って受け入れない。元と同じ`.xls`／`.xlsx`形式で保存できない場合は失敗させる。
- コメント、ハイパーリンク、文書プロパティ等の補助情報は初版では保持する。検出できたものは警告レポートに記録する。
- 補助情報の検出は完全な個人情報検出ではない。警告の有無にかかわらず、このツールはExcel出力全体を「個人情報なし」と保証しない。

Excelの出力レポートには、指定セル範囲の処理結果と、補助情報の検出状況を分けて記録する。補助情報の警告を無視した利用者がAIへ渡す可能性は残るため、ユーザー組織の持ち出し判断は別途必要である。

## 6. サンプリング

ファイル単位でサンプルモードまたは全件モードを指定する。サンプル件数とシードを設定し、同じ入力・設定・シードで同じレコードが選ばれるようにする。固定長のレコードやCSVの論理レコード、Excelのシート内データ行がサンプリング単位となる。

初期件数はファイルのレコード種別・例外パターンに応じて利用者が設定する。30〜100件は検討開始時の目安にとどめ、固定値にはしない。

## 7. エラー、出力確定、監査レポート

エラーはファイル単位で処理を停止する。変換表の未登録値、重複キー、レコード幅違反、対象範囲の重複、列不足、文字コード変換失敗、出力バイト幅不一致、Excel保存形式の不一致を成功扱いにしない。

エラー記録にはファイル識別情報、項目名、レコード／行／セル位置、エラー種別を含める。入力値・出力値・変換表の値を含めない。一時出力は成功・検証完了前に完成ファイルとして公開しない。

監査レポートには処理件数、マスキング件数、未登録件数、警告件数、検証結果、経過時間を含める。個人情報を含むサンプル値は記録しない。

## 8. 検証とテスト

合成データを用いて以下をテストする。

- 改行なし固定長ファイルのサイズ・レコード境界・直接抽出
- LF／CRLF付き固定長ファイルと行幅不一致
- 可変長氏名の前後空白正規化、半角／全角パディング、バイト幅超過
- 分割された10桁組合員番号の連結、変換、元範囲への再配置、先頭ゼロ保持
- 変換表の未登録・曖昧キー・文字コード不整合
- 引用符あり／なしのCSVフィールド状態の保持、引用符内の区切り文字・改行・`""`、引用符なし出力が不正になる変換値のエラー
- 固定幅NUL埋めCSVのブロック境界、末尾NUL除去と再付与、出力幅維持、容量超過と途中NULのエラー
- 複数シート、数式、書式、`.xls`と`.xlsx`のExcel処理
- サンプルの再現性、全件モード、元ファイル非変更、ログに個人情報が含まれないこと
- 出力後の固定長バイト幅、レコード数、CSV列構造、Excelシート名・形式の検証

処理時間は30万件相当の合成固定長・CSVデータで計測し、Excelは別に計測する。測定結果をもとに、必要ならユーザーと処理時間目標を定める。

## 9. セキュリティ上の限界と運用条件

- 変換表、入力データ、出力データはすべて管理下のローカル環境で扱い、ネットワーク送信機能は設けない。
- 未指定範囲はそのまま出力される。FILLERの個人情報有無はレイアウト作成者が確認する。
- Excelの補助情報は初版で自動削除しない。検出警告は参考情報であって、個人情報がないことの証明ではない。
- ツールはマスキング対象として指定されたフィールドを処理するもので、自由記述等に隠れた個人情報の自動検出を保証しない。
- 生成AIへの持ち出し可否は、このツールの処理成功だけで決めず、組織のデータ取扱い・AI利用ルールに従う。

## 10. 初版の対象外

- ファイル内容からの自動レイアウト推定、自動個人情報検出
- 固定長以外の形式に対する複数物理範囲の論理項目変換
- データベースのマスキング
- Excel補助情報の完全な安全化・個人情報不存在の保証
- 処理対象データを自動的に生成AIへ送信する機能
